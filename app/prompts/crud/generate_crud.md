# DATABASE RULES
## Referential integrity and constraints
Operations must fail with PostgreSQL's own constraint errors when given invalid foreign keys, duplicate unique values,
NULLs in NOT NULL columns or values violating CHECKs. Do not pre-validate in a way that changes the error class.
## Transactions and relationship operations
Operations touching several tables (create an order together with its lines, adjust stock) are ONE function so they are
atomic; arrays of composite/JSON inputs may be used for line items when needed (jsonb_to_recordset). A failure in any step
must leave NO partial changes.
## Concurrency
Where an invariant depends on a value read earlier (stock, counters, uniqueness not covered by a constraint), use atomic
UPDATE ... WHERE conditions or SELECT ... FOR UPDATE.
